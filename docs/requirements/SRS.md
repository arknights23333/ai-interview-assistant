## 2 产品定位与建设范围

### 2.1 目标用户与业务问题

主要用户为准备技术岗位面试的个人求职者。首批验收样例以 Java 后端岗位为主，系统结构应允许配置其他岗位方向。

系统需要解决以下问题：

1. 用户难以根据自身简历和目标岗位组织针对性的面试练习。
2. 练习后缺少可回看的逐题反馈和改进建议。
3. 学习资料分散，缺少基于个人资料的检索问答与专项练习入口。
4. 多个用户共用系统时，简历、面试记录、资料与模型配置缺少明确的访问边界。

系统提供面试训练辅助，不将 AI 分数直接解释为真实招聘结论。

### 2.2 建设目标与完成证据

| 目标 | 可检查的完成证据 |
| --- | --- |
| 形成完整的文字训练流程 | 用户登录后完成简历上传、文字面试、提交与评价，并能重新打开记录 |
| 支持个人资料问答 | 资料上传后能够完成向量化、检索、回答与来源展示 |
| 保证多用户数据隔离 | 两个测试账号之间的列表、详情、下载、导出、检索和 WebSocket 越权测试均被拒绝 |
| 验证聊天模型选择 | 同一业务场景可分别使用至少两家厂商的真实可用模型，记录实际调用的模型信息 |
| 完成后续六大业务模块 | 补齐语音面试、日程管理、知识库题库面试及数据导出 |
| 形成可交付工程 | 提供源码、部署说明、需求与设计文档、测试报告和用户手册 |

| 业务能力 | P0 核心版本 | P1 完整版本 | P2 可选增强 |

| 简历 | PDF/DOCX 上传、解析、异步分析、查看、删除 | 报告导出 | OCR、更多格式与高级版本比较 |

### 2.4 当前不纳入范围

当前不建设企业招聘 ATS、组织与部门体系、复杂 RBAC、付费订阅与支付、视频表情分析、本地大模型训练、声音复刻及第三方平台账号体系。第一版不实现 Embedding 模型切换、多个向量模型并行索引或语音面试过程中的自动供应商切换。

| 对比项 | 本地参考项目情况 | 本项目建设要求 |

| 语音供应商 | 当前处理链直接依赖千问 ASR/TTS 服务 | 统一内部协议，分别接入百炼和腾讯 |

| 角色 | 主要职责 | 边界 |

## 4 核心业务流程

### 4.1 简历与文字面试流程

登录 → 上传简历 → 文件校验与解析 → 异步生成简历分析 → 选择岗位、难度和聊天模型 → 创建文字面试 → 多轮作答与追问 → 提交面试 → 异步生成评价 → 查看或导出报告。

简历分析失败不应删除已上传文件；用户应能查看失败原因并重试。文字面试可按配置允许不关联简历，使用岗位方向题开始练习。

### 4.2 知识库与专项练习流程

创建私有知识库 → 上传资料 → 解析与分块 → 使用固定模型向量化 → 知识库可检索 → 选择资料进行 RAG 问答。

P1 扩展：选择知识库 → 异步生成题目草稿 → 用户检查、编辑并启用题目 → 选择方向和难度创建专项面试 → 作答 → 使用统一评价能力生成报告。

### 4.3 语音面试流程

登录 → 选择岗位及本场 LLM、ASR、TTS、音色 → 创建会话并保存配置 → 校验本人会话后连接 WebSocket → 录音与字幕 → LLM 流式回答 → TTS 合成播放 → 多轮交流 → 结束面试 → 使用问答转写记录生成评价。

暂停、刷新、断线重连均属于同一场面试的恢复，不应创建新的业务会话或改用全局最新语音配置。

### 4.4 日程流程

粘贴邀请文本或手动录入 → 提取候选字段 → 用户确认时间与时区 → 保存日程 → 日历或列表展示 → 到期提醒 → 用户更新完成、取消或改期状态。

AI 提取出的字段未经用户确认，不直接生成正式日程。

## 5 跨模块业务规则

| 编号 | 规则 |
| --- | --- |
| BR-001 | 当前用户身份必须从服务端验证通过的登录凭证取得，不信任请求体、查询参数或普通 `X-User-Id` 请求头声明的身份。 |
| BR-002 | 列表、详情、修改、删除、下载、导出、异步任务提交、RAG 检索和 WebSocket 连接都必须执行访问权限校验。 |
| BR-003 | 私有资源默认归创建者所有。关联简历、知识库、文档或面试时，必须先校验所有关联资源均可被当前用户访问。 |
| BR-004 | 同一逻辑操作重复提交不得产生重复面试消息、重复有效报告、重复有效向量或重复提醒。幂等标识和保存方式由设计文档定义。 |
| BR-005 | 长耗时任务应返回可查询的任务状态。失败应可识别，重试不覆盖已成功结果；对象删除后，旧任务不得重新创建其业务数据。 |
| BR-006 | 文档与查询使用同一 Embedding 模型和一致配置：`qwen3.7-text-embedding`、1024 维、稠密向量、COSINE。 |
| BR-007 | 修改或选择聊天模型不得触发知识库重新向量化。第一版不开放 Embedding 选择入口。 |
| BR-008 | 一场语音面试以持久化的面试会话记录为边界。ASR、TTS、音色和必要音频参数在开始时确定，暂停与重连沿用。 |
| BR-009 | 模型配置快照不包含 API Key。凭证更换不应改变面试记录中的历史模型标识；在用配置需要保留可解析的版本标识。 |
| BR-010 | 已完成面试的题目、回答和评价版本应可追溯。编辑题库或切换默认模型不得改写既有报告。 |
| BR-011 | 无有效检索证据时，应明确说明资料不足。回答引用必须能映射到本次已授权检索得到的真实文档片段。 |
| BR-012 | 系统默认以中文提供交互。时间统一存储为可确定时区的时间值，界面默认按 Asia/Shanghai 展示，解析含糊日期时要求确认。 |
| BR-013 | 收到客户端停止、取消或会话结束指令后，不再把旧轮次的字幕、回答或音频追加到新轮次。 |
| BR-014 | 模型输出必须按约定结构校验。截断、解析失败或缺少必要字段的输出不得标记为完整成功。 |

## 6 功能需求

以下表格中的“验收要点”用于需求评审；第 11 章列出跨模块验收场景。建议默认参数集中在第 13 章，均可在评审后调整。

### 6.1 账号与访问控制

| 需求编号 | 优先级 | 需求描述与验收要点 |
| --- | --- | --- |
| FR-ACC-001 | P0 | 用户提交账号、密码、邮箱和注册验证码；服务端验证邮箱验证码通过后才正式创建用户。账号唯一，邮箱唯一性按本地部分区分大小写、域名不区分大小写处理；重复账号或邮箱被拒绝。注册角色由服务端赋为 USER，不能通过请求自行取得管理员角色；昵称未填写时可由服务端提供初始值。 |
| FR-ACC-002 | P0 | 首版使用账号和密码登录，不要求每次登录进行邮箱或短信二次验证。通过 Spring Security 校验账号、BCrypt 密码摘要和启用状态；认证成功签发有有效期的 JWT，并建立 Redis 登录会话。错误密码、账号不存在或 DISABLED 状态不建立会话；密码及摘要不能返回给前端。 |
| FR-ACC-003 | P0 | 用户可退出；退出后对应登录会话凭证不可继续访问受保护资源；凭证过期时页面引导重新登录。 |
| FR-ACC-004 | P0 | 所有私有业务接口均校验身份与资源归属；未登录被拒绝，访问其他用户资源时不得泄露正文或敏感元信息。 |
| FR-ACC-005 | P0 | 登录失败与高成本 AI 请求受到可配置频率限制；用户修改请求中的身份字段不能绕过限制或获得其他用户身份。 |
| FR-ACC-006 | P0 | 提供注册与找回密码用途的邮箱验证码；验证码用途隔离、限时有效、一次使用，发送和尝试次数受限。验证码、过期时间及尝试次数存于 Redis，不加入用户资料表；发件服务通过 SMTP 接入，服务商和凭证另行配置。 |
| FR-ACC-007 | P0 | 用户可通过已绑定且验证过的邮箱重置密码；校验找回密码验证码后保存新的 BCrypt 摘要，并使该用户原有登录会话失效，要求重新登录。发送或找回接口不得因响应差异直接泄露邮箱是否已注册。 |
| FR-ACC-008 | P0 | 提供当前登录用户的基础资料，不能由请求中任意 userId 决定身份；资料包括账号、邮箱、昵称、头像、角色与状态等必要字段，不包含密码摘要。首版不采集性别等非必要个人资料；短信验证不在首版范围。 |

### 6.2 简历管理与分析

| 需求编号 | 优先级 | 需求描述与验收要点 |
| --- | --- | --- |
| FR-RES-001 | P0 | 用户可上传 PDF、DOCX 简历；校验文件大小、实际格式与解析结果，超限、损坏、受密码保护或无可用文本时返回明确结果。 |
| FR-RES-002 | P0 | 保存文件基础信息、归属和处理状态；同一用户重复上传相同内容时提示复用或明确创建新记录，不泄露其他用户是否已有相同文件。 |
| FR-RES-003 | P0 | 异步解析和分析简历；展示等待、处理中、成功、失败状态，任务失败后保留可处理的原始资料。 |

## 7 状态与异常处理

### 7.1 状态模型

| 对象 | 主要状态 | 允许的变化与约束 |
| --- | --- | --- |
| 异步处理任务 | 等待、处理中、成功、失败、取消 | 等待进入处理后结束为成功或失败；重试产生可追踪的新尝试；删除关联资源后取消或丢弃结果 |
| 面试会话 | 未开始、进行中、已暂停、已结束 | 可从暂停恢复；结束后不可通过普通作答接口继续修改 |
| 评价任务 | 未提交、等待、处理中、成功、失败 | 与面试状态分开记录；面试已结束不等于报告已成功 |
| 知识库题目 | 草稿、已启用、已归档 | 只有已启用题目参与新面试；历史会话使用原快照 |
| 日程 | 待进行、已完成、已取消 | 改期保留可识别的更新时间；过期展示与取消语义区分 |

具体枚举名称由设计文档统一，不以复用参考项目命名为前提。

### 7.2 统一异常要求

| 场景 | 系统行为 |
| --- | --- |
| 未登录、凭证过期或已退出 | 拒绝受保护操作，前端提示重新登录，不返回业务数据 |
| 资源不存在或无权访问 | 不返回资源正文；对普通用户可统一提示“资源不存在或无权访问” |
| 文件格式不支持、解析为空 | 返回可理解的原因，不向 AI 提交无效内容 |
| 请求超时或模型限流 | 明确显示失败或稍后重试；只对可安全重试的阶段执行有限重试 |
| 流式输出中断 | 保留已确认内容和未完成标识，允许重试或重新生成，不伪装完整成功 |
| 对象被删除但旧任务返回 | 丢弃迟到结果并完成任务清理，不恢复对象或重新写入有效向量 |
| 同一操作重复提交 | 返回已有结果或处理中状态，不重复推进业务 |
| 第三方返回敏感异常 | 面向用户返回分类错误；内部日志保留追踪信息并脱敏 |

## 8 数据需求与生命周期

### 8.1 核心数据对象

| 对象 | 必须表达的信息 | 归属与关联 |
| --- | --- | --- |
| 用户 | ID、账号、已验证邮箱、密码摘要、昵称、头像、角色、状态、创建时间、更新时间 | 身份源，不能由客户端指定为他人；注册角色由服务端赋值 |
| 登录会话 | 用户、有效期、退出或失效状态 | 关联用户，不在日志中记录完整凭证 |
| 简历及分析 | 文件元信息、解析状态、分析任务和报告版本 | 私有，归上传用户 |
| 知识库与文档 | 知识库名称、文档、分块、处理状态、模型及策略版本 | 私有；P2 公共资料另有明确开放范围 |
| 向量片段 | 文档、知识库、片段定位、向量模型与维度 | 检索结果必须可追溯到授权文档 |
| 面试及消息 | 用户、模式、岗位、难度、问答、进度、模型配置标识 | 私有；题目与答案按轮次保存 |
| 评价报告 | 对应面试、任务状态、分数与理由、规则及模型版本 | 私有，报告版本可追溯 |
| 题库题目 | 来源、题目、参考答案、评分要点、方向与状态 | 私有；生成面试时复制必要快照 |
| 日程与提醒 | 公司、岗位、时间、状态、提醒规则和发送记录 | 私有，提醒具有幂等标识 |
| 模型连接配置 | 展示名、Provider、模型、地址、开放状态和凭证引用 | 平台配置，不属于普通用户可读业务数据 |

本表规定数据含义，不直接指定最终表名、字段类型或数据库关系实现。

### 8.1.1 首版用户资料约定

用户表已通过 `V1__create_user_table.sql` 定义为 `app_user`，具体列类型和约束以迁移脚本为准。十个字段为：`id`、`username`、`email`、`password_hash`、`nickname`、`avatar`、`role`、`status`、`created_at`、`updated_at`。

- 账号唯一且区分大小写；邮箱保留本地部分大小写，仅将域名转小写；数据库唯一索引按同一规则比较，域名大小写变体不能重复注册。
- 角色为 `USER` / `ADMIN`，默认 `USER`；状态为 `ACTIVE` / `DISABLED`，默认 `ACTIVE`。
- 昵称允许重复；头像允许为空；创建与更新时间采用可确定时区的时间值，更新时间后续由应用维护。
- 正式注册先验证邮箱再建用户，因此首版不增加独立的邮箱已验证字段；验证码等临时数据放在 Redis。
- 简历内容放在简历模块，不塞进用户资料表；开发测试账号与正式注册流程分开管理，不把开发账号写成生产初始化需求。

### 8.2 留存与展示

用户业务记录默认保留到用户主动删除。测试数据应与正式演示数据区分，避免通过初始化脚本泄露真实简历。全文解析结果、引用片段与日志只保存业务所需内容；原始语音默认不落盘。

历史报告保存生成时的模型标识与规则版本。系统只展示已保存报告，不通过重新调用模型来“恢复”历史报告。

### 8.3 删除与关联处理

1. 删除简历：移除原文件、解析全文与简历分析结果；历史面试可保留已发生的问题、回答和评价，但解除简历关联，不继续保留简历全文副本。
2. 删除知识库或文档：停止或作废相关未完成任务，移除原文件、分块与有效向量，后续检索不得再命中；历史问答和已经完成面试的快照是否保留需在删除确认中说明。
3. 删除历史面试或 RAG 会话：同步移除或不可逆地使其关联消息、报告不可访问，禁止旧任务重新生成可访问记录。
4. 删除题库题目：不再参与新面试；已完成面试保留题目和评分要点快照。
5. 数据库记录与对象存储清理发生部分失败时，记录待清理状态并重试，不向用户暴露仍可读取的旧文件地址。

默认历史问答和已完成面试快照独立保留，用户可单独删除；此项在界面明确告知。账号注销与自动过期清理不属于本版已承诺功能。

## 10 技术与外部依赖约束

### 10.1 已有工程与规划

截至 2026-10-24，个人项目使用 Java 25、Spring Boot 4.1.1、Gradle 9.8.2、MyBatis-Plus 3.5.17，以及 `front/` 下的 Vue 3、TypeScript、Vite、Vue Router 和 Pinia。后端源码、资源和应用构建脚本位于 `app/`；根目录保留 Gradle Wrapper 和版本目录。持久层由初始 JPA 骨架改为 MyBatis-Plus，数据库结构由 Flyway 管理，不再依赖 Hibernate 自动建表或实体校验。

认证方案已确定为 Spring Security + JWT + Redis + BCrypt。当前只接入 Security 依赖并使用默认 Basic Auth 验证了用户查询；数据库账号认证、正式登录与退出、JWT 签发与校验、Redis 登录会话仍待实现。已存在 `app_user` 迁移、`UserPo`、`UserVo`、Mapper、Service 与 `R<T>` 统一响应基础代码；不能将按 ID 查询成功当作已完成登录或数据隔离。

PostgreSQL（开发镜像包含 pgvector）、Redis、Flyway 和 Apifox Helper 已接入基础开发流程。pgvector 的业务向量表与 RAG、Spring AI、Redis Stream、S3 兼容存储及邮件发送仍属后续工作；依赖存在或镜像包含扩展，不代表业务已实现。版本依据及接入状态详见 [技术栈与接入状态](../TECH_STACK.md)。

邮箱用于注册所有权验证与找回密码，首版不做短信验证。模型选择继续以 [模型选型文档](../MODEL_SELECTION.md) 为准，不改变既有固定 Embedding 和按面试固定语音配置的决策。

### 10.2 外部服务边界

| 依赖 | 使用目的 | 不可用时的业务结果 |
| --- | --- | --- |
| 百炼及其他聊天模型服务 | 分析、面试、问答与评价 | 分类提示失败，保留已确认记录，允许有限重试 |
| 固定 Embedding 服务 | 文档与问题向量化 | 新资料不能成为可用检索源；不切换其他模型继续查询旧向量 |
| 百炼与腾讯语音服务 | ASR/TTS | 当前语音步骤明确失败，可重试或结束，不静默换厂商 |
| 对象存储 | 原始简历与资料 | 上传或下载返回失败，不创建声称文件已存在的成功记录 |
| Redis 与任务执行组件 | 限流、会话辅助与异步任务 | 按设计进入失败或降级状态，不绕过身份校验与权限约束 |

模型访问权限、免费额度、余额、地域与限流属于运行条件，不在本文承诺永久免费或固定价格。

### 10.3 前后端交互要求

基础业务使用明确的请求与响应契约；文字流式交互使用约定的事件协议，语音使用统一 WebSocket 消息。接口设计必须定义错误分类、分页、流式开始与结束、中断、轮次标识和幂等行为。

普通 JSON 业务响应采用 `R<T>`，字段为 `code`、`msg`、`data`，当前约定成功业务码 200、通用失败业务码 500；业务码与 HTTP 状态码分开定义。全局业务异常以及 Security 的未认证、无权限响应应采用一致的 JSON 结构；当前异常处理与安全错误适配尚未完成。PO 不直接作为接口响应，展示对象使用 Vo。

接口文档通过 IDEA 的 Apifox Helper 读取接口代码、类型和 Javadoc 后主动同步至 Apifox。根目录 `.apifox-helper.properties` 保存可提交的公共生成规则；个人访问令牌、真实登录凭证留在本机，不提交。本文不提前规定全部 URL、字段名和厂商 SDK；接口文档与需求编号建立关联。

| 密码长度 | 8～64 个字符，待安全设计确认 | 摘要算法已确定为 BCrypt；需按所选实现的字节长度限制校验，不能仅按字符数放行 |
| 登录有效期 | 2 小时 | 仍为建议；JWT 与 Redis 会话有效期需一致，首版可过期重新登录，不强制引入刷新令牌体系 |
| 邮箱验证码 | 6 位随机数字、5 分钟有效、同邮箱 60 秒发送间隔、连续 5 次错误后失效 | 建议值，尚未实现；注册与找回用途隔离，一次使用，并限制邮箱/IP 请求频率 |
| 单份简历上限 | 10 MiB | 服务端与前端一致，不以扩展名代替实际格式校验 |
| 单份知识文档上限 | 20 MiB | 解析后字符数和可生成片段数另设保护上限 |
| 单次文字回答长度 | 5000 个字符 | 超限在提交前提示，服务端复核 |
| 默认主问题数与追问 | 5 个主问题，每题最多 1 次追问 | 允许在服务端规定范围内选择，不无限追问 |
| 自动重试 | 仅可安全重试阶段最多额外 2 次 | 不对已确认提交或有副作用操作盲目重试 |
| 日程提醒 | 提前 15 分钟，站内提醒 | 在线送达目标为到期后 60 秒内 |
| 评分建议 | 百分制；准确性 50%、完整性 30%、条理性 20% | 仅作为 D-004 的评审起点，确认前不宣称量表已经验证 |

## 14 主要风险与处理

| 风险 | 对交付的影响 | 处理方式 |
| --- | --- | --- |
| 模型名称、权限或免费额度变化 | 已配置模型不能真实调用 | 接入时复核并真实验证，保持展示配置与可用能力一致 |
| 多用户归属校验遗漏 | 简历、资料、报告或语音会话越权 | 从 M1 开始执行 A/B 账号测试，覆盖文件和向量检索 |
| 第三方输出不稳定 | 出题或评价不完整、结构化解析失败 | 固定输出结构、版本与样例，有限重试，失败状态可见 |
| 跨厂商语音格式差异 | 播放失败、时序错误、延迟增加 | 统一内部消息和格式描述，分阶段验证四组合 |
| 学习和开发时间不足 | 六大模块同时推进导致核心流程不完整 | 优先完成 P0，按里程碑验收；需要调整任务书范围时明确记录并与导师对齐 |
| 性能目标口径不清 | 演示结果无法证明达标 | 在压测前关闭 D-002、D-003，区分应用与供应商耗时 |
